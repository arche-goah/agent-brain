- **`ci-watch.sh pr` counts a check-run by its conclusion, not by a status GitHub forgot to flip** (test: T1). Measured 2026-10-12 on a suite PR: check-run `release-preflight` read `status=in_progress`, `conclusion=success`, `completed_at` set, while its workflow run was completed/success — `gh pr checks` bucketed it as `pending` for good, and the watch ended `UNKNOWN: timeout` on an all-green PR; no timeout reaches a check that never flips. While `pr checks` reports pending entries, the watch now reads the head commit's check-runs and recounts every pending entry whose check-run carries a non-null conclusion (success/skipped/neutral → done, anything else → RED); a pending commit status, a check-run without a conclusion, or any unreadable answer keeps waiting. ref mode is untouched: it reads workflow runs, which were already completed in the measured case. Fixture: stale green → GREEN on the first poll, stale failure → RED, genuinely running → still waits, commit status without check-run → still waits (`ci-watch-test.sh`, 30 checks).
