- **A shared-memory request's state is written, not rebuilt from words: LOG requests get an id, replies name it, and `shared-memory-post.py` writes requests and replies with their fields.** (test: T1) (level: writer; higher: design — a fully generated LOG (each message a file, `LOG.md` written by the index generator) needs a measurement first: two runs byte-identical and no hand entry lost, and the monthly rotation must know the generated part; debt: free-form LOG pings stay prose, the heading parser keeps five live shapes, collaborators on an older core keep writing requests by hand until their update, and the shared-memory repo has no CI — the lint runs only where a machine wired its commit hook) Measured 2026-10-19: of 23 requests the start report listed as open to one instance, 21 were long answered — the answers just did not repeat the request's words. The readers rebuilt both the identity and the state of a LOG request from prose: `open-items.py` keyed it by date, sender and its first 40 characters (15 fixes in 7 days: collisions, cuts at a blank, one entry inheriting another's class and counter), and the inbox closed it when a reply repeated the title, a `re <x>`, or the numbers (5 fixes in 9 days); 9 files tried to answer a LOG request in prose (`answers: LOG 2026-10-15 <sender> — <title>`, commit SHAs) that no tool could follow. Now: every LOG heading has a derived id `<area>/LOG@<date>#<n>` (n = the n-th heading that day in that LOG, whoever wrote it — counting per sender gave two parties' entries one id, measured on the real repo while building this; stable on append and across the monthly rotation; `shared-memory-parties.py`). The inbox prints it instead of `(LOG)`; `answers:`/`claims:`/`closes:` of a file, or a later LOG entry that carries the id, settle the request — the asker's own entry only when its heading says it is settled, so a reminder settles nothing; a heading with a settled status (`done`, `answered`, `closed`, `decided`, not only `info`) is a report, not a request. From `STATE_SINCE` = 2026-10-20 only the id settles; older entries keep the word rules, or the requests other parties closed by title would open again. `open-items.py` keys a LOG request by the id: class and counter belong to it and survive a reworded heading; the `(n)` suffix and the text fingerprints that guarded reused ids are gone. **One-time effect:** classes and repeat counters stored under the old key `<area>/LOG <date> <sender>: <first 40 chars>` no longer match — each open LOG request is unclassified and counted from one once after the update. `open-items-gate.cjs` names the id. New `scripts/shared-memory-post.py request|reply|note`: the file with full frontmatter (`next:` resolved to the addressees' devices), one LOG line pointing at it, the index regenerated; it refuses an addressee `parties.json` does not know, a reply without `--answers`, an `--answers` target that names nothing, an unset `SHARED_MEMORY_SELF`, a folder that is not an area — and writes nothing then. Lint check 11 `relations` (entries dated `STATE_SINCE` or later; also at commit through `--staged`): a relation value that names no file stem and no LOG id (archive included); a LOG heading to a party that asks something and points at no file; at commit, a LOG heading inserted, edited or removed within a day that stays (the ids after it would shift — append only; a whole day rotated out or a new heading for a day that had none shifts nothing).
