- **`ci-watch.sh pr` no longer says GREEN while a workflow run of the head commit is still open.** (test: T1) Measured 2026-10-16 on a core PR: the fast CodeQL run finished with 4 green checks, but the main workflow run had started 52 s before the verdict (status in_progress, ten jobs queued) and had no check listed yet. The watch said `GREEN — 4 checks, none failing`, and a merge on that word would have been unverified. Before GREEN, pr mode now reads the head commit's workflow runs (`actions/runs?head_sha=`); any run that is not completed means no verdict yet, and the wait is named once. An unreadable answer keeps the previous behaviour, and the deadline bounds every wait. Fixtures: listed checks green with a run still open = timeout (the old script says GREEN here — negative control); the open run completes = GREEN.
