- **`public-text-guard.cjs` scans the text that gets published, not the whole command.** (test: T2) (level: writer; higher: design — one post tool that all three outgoing-text guards hang on would still need the guards as enforcement at the shell, a tool can be bypassed and a PreToolUse hook cannot, so it brings convenience first; debt: three guards — this one, `instance-key-gate.cjs`, `mechanism-guard.cjs` — still parse `gh`/`git` commands each on its own, one shared extraction is the next step) Since 2026-10-10 the guard scanned the whole shell command and masked known path forms (the home part of `/Users/<login>`, then every slash word whose parent folder exists). Every new form was a new false alarm, and the masks hid real text: measured on the macOS instance 2026-10-19, a name in a shell comment and a name in a path whose folder did not exist yet both blocked; a path-shaped word INSIDE a PR body was masked and passed unchecked; `git commit -m<text>` with the text attached was not seen. The guard now reads the command as the shell does — words, quotes, `;`/`&`/`|`/newline segments, `#` comments, `$(...)` kept whole; in PowerShell a backslash is a path separator, not an escape — and scans exactly what reaches GitHub: the values of `--title/-t`, `--body/-b`, `--notes/-n`, `--subject`, `-f/-F/--field/--raw-field`, the `gh api` endpoint, `git commit|tag -m/-<flags>m/-m<text>/--message`, and every handed-over file (`--body-file`, `--notes-file`, `--input`, `--file`, `gh pr -F <file>`, `key=@file`, `$(cat <file>)`). Paths, flags, the working directory and comments are never published and never scanned. A command it cannot read to the end (a heredoc, an unbalanced quote) is scanned whole, as before. Named limit: text in a shell variable (`--body "$BODY"`).
