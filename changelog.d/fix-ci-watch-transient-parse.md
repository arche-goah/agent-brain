- **ci-watch: an unparseable gh reply right after a push is a wait, not a verdict.** (test: T1) Measured 2026-10-10 on a core PR after its main merge: first poll "no checks yet — waiting", second poll exit 2 "UNKNOWN: unparseable gh pr checks output" while the run was being registered; a round later eleven checks were green and the watch had already given up. A reply that is not the expected JSON is now handled like "no checks yet": the watch keeps polling and says so; only three unparseable polls in a row (`CI_WATCH_UNPARSED_MAX`) end it as UNKNOWN, naming the repeat. Same in ref mode for `gh run list`. Fixture +3 (unparseable once then green exits 0 in pr and ref mode; always unparseable exits 2 and names the repeat); the first case is red against the previous script.
