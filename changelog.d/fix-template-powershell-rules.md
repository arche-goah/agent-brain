- **Template: the git/gh permission rules exist for the PowerShell tool too.** (test: T1) Follow-up to #371 from its Windows review. Claude Code's docs (tools-reference, "PowerShell tool"; permissions, "PowerShell", read 2026-10-16): a `Bash(...)` rule does not reach the PowerShell tool, which has its own rules of the same shape — and a Bash DENY rule switches the PowerShell tool off for the whole session unless a scoped PowerShell rule exists. #371 added nine Bash deny rules (force pushes, deletes), so a brain bootstrapped from that template on Windows would have lost its PowerShell tool silently, and a `git push` typed into PowerShell had no rule and asked. Now every git/gh rule of the template stands twice, `Bash(...)` and `PowerShell(...)` with identical strings: 31 allow, 4 ask (push to main), 9 deny. The core-script rules stay Bash-only, because the core's scripts run from Git Bash (working rule #8). Measured on Windows: `onboarding-verify-test.sh` passes, the template parses; a brain bootstrapped from this template read by `decision-readiness.py` (#372) and `autonomy-diagnose.py` (#368) shows no everyday dialog (79 allow, 11 ask, 23 deny). Not measured: a live PowerShell call against the new rules (a settings change on a running brain is the operator's).
