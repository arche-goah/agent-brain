- **`watch-gate`: a PR opened or merged in a repo without workflows no longer demands a CI watch, and the template shows WHICH reaction lacks a watcher.** (test: T1) Measured 2026-10-16 on the macOS and the Windows instance: `gh pr create` / `gh pr merge -R <repo>` into a private repo without Actions blocked the turn end with every watcher alive. The repo flag was taken as "CI started" without asking whether the repo runs CI. Both instances read the block as an unexplained false alarm, because the template's fixed line ("A reaction is expected, but no watcher is running") dropped the gate's own reason. Now a named repo counts only when a local checkout of it, or one `gh api …/contents/.github/workflows` call, shows workflows. Anything not measurable still counts as CI, so the gate errs toward the watch. The template captures the reason (`No watcher for an expected reaction: CI started on <repo> …`). `originSlug` no longer leaks git's "not a git repository" to stderr. Fixtures: a named repo without workflows passes, both via a 404 and via a local checkout; controls: a local checkout with workflows blocks, an unmeasurable repo blocks; the old gate blocks the real merge case.
