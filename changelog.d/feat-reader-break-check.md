- **The pre-commit hook holds a commit that removes a phrase a reader greps from its file** (test: T1 - `scripts/test-reader-break-check.sh`, 8 cases incl. the history mode) (level: writer; higher: design - readers that name an invariant instead of a sentence, not built: ledger checks and memory anchors grep text today and need a holder now; debt: readers of other file types, e.g. `jq` on JSON, are not read) - new `scripts/reader-break-check.py`, step 4e of `helpers/git-hooks/pre-commit`, in every repo. A ledger `check: grep -q "<phrase>" <file>` and a memory `home: <file> :: <phrase>` broke only at the next start check after a diet cut their sentences. Readers come from the staged tree, so a commit that rewrites the reader passes; negated checks (`! grep`, `grep -v`) are skipped. Replay, shipped as `reader-break-check.py --history <date>` (each commit judged with the readers of its own tree): on one brain since 2026-09-01, 4404 commits judged, 5 held, 7 broken readers, on 4 days; one of them, a memory anchor, was still broken and unseen (the memory lint checks binding memories only). Limit: a reader that greps a regex is compared as text, so a regex phrase is never held.
- **pre-commit runs a covering fixture without the commit's git environment** (test: T1 - the reader-break fixture under `git commit -- <paths>`, red before, green after) (level: writer; higher: design - each fixture isolating its own git env, not built: the hook is the one place fixtures are started from, so one line there holds every fixture; debt: a fixture run by hand inside a hook-like env is not covered) - `covers_check` starts fixtures under `env -u GIT_INDEX_FILE -u GIT_DIR -u GIT_WORK_TREE -u GIT_PREFIX -u GIT_CONFIG_PARAMETERS -u GIT_CONFIG_COUNT` (the last two: a commit made with `git -c core.hooksPath=…` handed that setting to the fixture's own commits, which then ran this hook).
