- **A bot PR (dependabot) no longer turns the leak scans red for a missing watch list.** (test: T0) Measured 2026-10-25 on the first dependency bump after the text-leaks notice landed (#109, `actions/setup-python` 7.0.0 → 7.1.0): both the `leaks` job of CI and the `text leaks` workflow failed in seconds with `leak-scan: LEAK_NAMES_REQUIRED=1 but no watch list (LEAK_NAMES_JSON secret …)` — GitHub hands a pull_request run triggered by dependabot no repository secrets, so the required list never arrives and every dependency bump would be red from now on (with #107 in place an open red PR also blocks every tag). Both workflows now set `LEAK_NAMES_REQUIRED` to `0` when `github.actor` is `dependabot[bot]`: a bot body names nobody from the watch list by construction, and the generic checks (private addresses, home paths, MACs, emails) still run on it; every other actor keeps the requirement. (level: reader; higher: writer — a Dependabot secret of the same name would give the bot run the list too, which is a repo setting, not a workflow change; not built: the list is instance material that a bot body cannot carry, so requiring it there buys nothing; debt: the exception is keyed on the dependabot actor name only — another bot would need its own line)
