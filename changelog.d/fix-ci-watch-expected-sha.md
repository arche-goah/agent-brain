- **`ci-watch.sh pr` can wait for the commit just pushed: `CI_WATCH_SHA=<sha>`.** (test: T1) Measured 2026-10-16 on a core PR: a merge of main into the branch was pushed, and a watch armed in the same turn said `GREEN — 14 checks` within a minute. All 14 belonged to the OLD head; GitHub still reported the previous `headRefOid` and its checks, while every run of the new head was pending. With `CI_WATCH_SHA` set (full or short sha), pr mode counts nothing until the PR's head is that commit, and says once that it waits for it. Without it the behaviour is unchanged. The fixture's closing line no longer carries a hard-coded count ("all 30 checks", while 52 ran). Fixtures: head still old then flips = GREEN on the new head; head never reaches the sha = timeout; control without the variable = the old head's green counts, as before.
