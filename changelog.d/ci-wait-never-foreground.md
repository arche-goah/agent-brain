- **CI is never waited for in the foreground.** (test: T1) A core CI run takes about 15 minutes; a session that ran `ci-watch.sh` (or `gh run watch`, `gh pr checks --watch`) in the foreground was blocked for that time, and several PRs in a row cost hours. Measured 2026-10-13 on the macOS instance: 65 of 263 ci-watch calls in three days ran in the foreground. `mechanism-guard.cjs` gets a rule field `foreground_only` (fires only for a Bash call without `run_in_background`; Monitor counts as detached), and the core's `mechanism-rules.json` blocks the three CI waits in the foreground. Working Rule #9 says it in words. Fixture in `test-guards.sh`: the three foreground forms block; `gh pr checks` once, Monitor, and `run_in_background` pass.
