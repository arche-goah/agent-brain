- **`ci-watch.sh` waits out a GitHub API rate-limit block instead of dying blind.** (test: T0) (level: reader; higher: writer — the many parallel pollers that trip GitHub's secondary limit are the cause, and a machine-wide lock per repo+PR would cut them, but attaching a second watch to the first one's verdict (its own `CI_WATCH_SHA`, its own timeout) is not small and stays a separate change; debt: one ci-watch per repo+PR per machine — two sessions arming the same watch still both poll) Measured 2026-10-19 with three sessions on one machine and one GitHub account: `gh pr checks` answered "API rate limit already exceeded for user ID …" while `gh api rate_limit` still showed thousands of requests free — GitHub's secondary limit. The watch printed `CI-WATCH UNKNOWN … rate limit already exceeded`, exited 2 at once and was blind from then on while CI kept running. Every gh call of the script now goes through one wrapper: a rate-limit answer (primary or secondary — "rate limit", "abuse detection", HTTP 429 / "Too Many Requests"; GitHub's 403s for both limits carry the "rate limit" wording, a bare 403 stays a normal error) prints ONE line `CI-WATCH BLOCKED: GitHub API rate limit — waiting until <time>` per block, waits until the reset `gh api rate_limit` names for an exhausted core or graphql resource, otherwise backs off exponentially from 60 s to 15 min with jitter, and resumes polling; the end of a block is named. The blocked time EXTENDS the verdict deadline, so a block never eats the CI's own time. A block longer than `CI_WATCH_RL_CEILING` (default 7200 s — a primary window resets hourly, so two hours of block is no longer weather but a revoked token or an abuse flag) ends as `CI-WATCH UNKNOWN: rate-limited for <n>s … (do NOT read as green)`. The exit contract (0 green, 1 red, 2 could not measure, 3 no CI) is unchanged. Fixtures in `ci-watch-test.sh` (stub `gh`, no real API): three secondary answers then green, a primary reset then green, two separate blocks (two BLOCKED lines), a 3 s block against a 1 s timeout followed by one more poll, the ceiling (UNKNOWN naming the block), a block on the swallowed `mergeable` read, and six blocked runs reads in ref mode (the old code gave up after five) — all green with the expected BLOCKED count. Run against the previous script the same fixtures fail 13 assertions; with the deadline extension removed, the timeout case fails. `CI_WATCH_SCRIPT=<path>` points the fixtures at another copy for such a negative run, and each case now starts from a fresh stub state.
