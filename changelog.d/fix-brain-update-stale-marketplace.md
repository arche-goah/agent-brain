- **`brain-update.sh` no longer moves `core/` when the marketplace refresh failed.** (test: T2) Measured 2026-10-22 on a Windows brain: `claude plugin marketplace update` failed ("not refreshed — continuing with cached state"), the cached core plugin still said 1.4.1 while the brain sat on v2.0.3, and the run checked out v1.4.1, committed the pin and pushed it — every other machine of that brain pulled the downgrade until it was reverted by hand. A pin read from a cache this run could not refresh is not the released state, so a failed refresh now leaves `core/` where it is and prints a FAIL line naming the skipped move; nothing moves, so nothing is committed or pushed. Plugins are untouched by this change (their update reads the same cache and stays as before). Fixture `scripts/brain-update-test.sh`: the real script against a fake brain on v2.0.0, a stub `claude` that fails every call and a cache on 1.0.0 — `core/` stays and the FAIL line is printed; the case fails against the old script (checked). (level: writer; higher: design — compare the target tag with the committed pin and refuse only downgrades, not built: a stale cache can also name a wrong newer tag, and "no fresh pin, no move" covers both; debt: none)
