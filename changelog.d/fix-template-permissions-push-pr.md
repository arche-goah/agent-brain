- **Settings template: push, `git -C` work on neighbour repos, pull requests and issues no longer raise a permission dialog; force pushes are denied.** (test: T1) Measured 2026-10-16 on a collaborator's brain (core v1.3.41; v1.4.4 has the same template): every commit and push raised a dialog the human did not understand ("why do you ask me the bash command?"), and the AI read push as "needs the operator" — one of the main causes of an instance that asks before every step. The template put `git push*` under `ask` and had no rule for `gh pr`. Now `allow` carries `git push*`, `git -C * push*`, `git -C * add/commit/status/log/diff*`, `git [-C *] pull --ff-only*`, `gh pr *`, `gh issue *`, `gh run list/view*`; `deny` carries `git push --force*` / `-f*` (also with `-C`). Settings edits (`settings.json`, `settings.local.json`, `.mcp.json`) stay `ask`. The limits that matter are carried by the gates, not by a dialog: `mechanism-guard` (merge, tag, raw API merge), the instance's operator-only list, `shared-working-copy-guard`. **Existing brains do not pick this up** (the template is read at bootstrap): a human moves the push lines from `ask` to `allow` in `.claude/settings.json` and adds `gh pr *` — the AI may not grant itself permissions.
