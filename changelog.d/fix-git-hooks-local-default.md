- **Git hooks: a new brain gets them in its own git config, the user-wide setting is opt-in** (test: T1 `scripts/test-install-git-hooks.sh`, 10 cases, 5 of them red against the old script) (level: design; higher: none — where the hooks path is written IS the design question; debt: a setup that wants the hooks in its suites and shared memory must say so, `install-git-hooks.sh --global` or `BOOTSTRAP_GIT_HOOKS=global`; machines that already carry the global setting keep it, nothing is rewritten). Measured in the fresh-brain trial of 2026-10-21: `bootstrap-brain.sh` set `core.hooksPath` globally, and a repo-local pre-commit hook in an unrelated repo stopped running; for a third party that switches off husky or pre-commit in every repo. Decision of the core owners: local by default, global only on opt-in. `install-git-hooks.sh` writes `--local` unless `--global` is given and refuses outside a repo; `--check` accepts either, the local value deciding when both are set (as git itself does); `bootstrap-brain.sh` reads `BOOTSTRAP_GIT_HOOKS`; the session start names the brain's own config.
