- **One git login path for every brain: HTTPS to github.com goes through gh.** (test: T1) Two instances measured different setups on 2026-10-18: on one Mac about 30 HTTPS pushes a day ran without a prompt because a token sat in the keychain; on the other, an HTTPS push hung for minutes and a login window opened on the operator's screen, because `osxkeychain` had no github.com entry and the AI cannot see that dialog. Agreed between the two instances: every brain lets `gh` answer git's credential question (`gh auth setup-git`) — it uses the token gh already holds, needs no key management and works the same on Windows; SSH stays allowed but is no required path. `bootstrap-brain.sh` sets it when gh is logged in; `preflight.sh`/`preflight.ps1` check it; the session start names a brain without it (local git config only, no network). The checks match the subcommand `auth git-credential`, not the program spelling: on Windows `gh auth setup-git` writes the full quoted path (`!'C:\Program Files\GitHub CLI\gh.exe' auth git-credential`, measured on the Windows instance).
