- **`skill-gate` counts a skill a subagent loaded in its own transcript, and a `skill-gate.json` rule counts the SKILL.md read its block message offers.** (test: T2) Measured 2026-10-15 on a collaborator's Windows instance: two subagents loaded the required skill with the Skill tool (one also read its SKILL.md), and their edits stayed blocked (five `BLOCKED` lines in `.claude-state/skill-gate.log` within one minute) until the parent session loaded it. Cause, read from the Claude Code 2.1.301 binary and the transcripts of this machine: a hook fired inside a subagent receives the PARENT session's `transcript_path` plus `agent_id`, while the subagent writes its own transcript to `<dir>/<session>/subagents/agent-<agent_id>.jsonl` — the gate read only the parent's, so "a subagent loads for itself" never held. Second gap: rules from `skill-gate.json` carry no SKILL.md path, so the Read the block message offers as the alternative never counted there. Now the gate also reads the subagent's own transcript when the event carries an `agent_id` (missing file: logged, parent alone decides as before), and for a rule without a file a Read of `<any>/skills/<bare name>/SKILL.md` counts. Fixture `scripts/test-skill-gate.sh`: subagent loaded it = allow; neither loaded it = block; parent loaded it = allow as before; `skill-gate.json` rule plus a Read of its SKILL.md = allow, of a different SKILL.md = block (control); subagent transcript missing = parent decides; three of the new cases fail against the previous gate.
