- **The leak scan sees commit identities, commit messages, post text and private addresses, and CI scans with a names list.** (test: T1) Before the second history cut (2026-10-18) the repo held 84 commits with a private author address, 22 messages and 164 file versions naming people while CI stayed green, for three reasons: the scan read working-tree files only, it had no email class, and CI ran without a names list (the code said person names "cannot occur in shared repos"). `scripts/leak-scan.py`: new class `email` (everything outside the GitHub noreply forms and the reserved example domains); `--commits RANGE` scans author, committer and message of every commit; `--text FILE` scans free text; the watch list may come from the secret `LEAK_NAMES_JSON`, and `LEAK_NAMES_REQUIRED=1` turns a missing list into exit 2 instead of a silent pass. Findings from the secret list, and every email/person finding inside GitHub Actions, are printed redacted — a public CI log is a publication. CI: the `leaks` job scans the tree and the commits of every PR (base..head) and push (before..after, the whole history on a new ref); the new workflow `text-leaks.yml` scans PR titles and bodies, comments and reviews. Repos that adopt this set the secret `LEAK_NAMES_JSON` (`{"names": [...], "instances": [...]}`). Limit: a squash merge takes the MERGER's commit address from their GitHub settings — the push check turns main red afterwards, only "Keep my email addresses private" on every collaborator's account prevents it. Collaborator logins (`accounts` in the list) are masked before the name check: a login is the public account every PR shows. Fixture `scripts/test-leak-scan.sh` (12 checks, a clean range and a bare name next to a login as negative controls).
