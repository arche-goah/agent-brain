- **N shared-memory channels: the session start and the live watch read every channel this instance belongs to, each with its own cursor, lock and label.** (test: T1) Operator decision 2026-10-24, agreed by both core parties: the AI sessions on one operator's own devices need a private place to coordinate, and groups of parties need channels with their own members. Measured on the Windows instance the same day: a private repo in the shared-memory format already worked with `shared-memory-post.py`, `shared-memory-inbox.py` and `shared-memory-watch.sh` through `--repo` / `SHARED_MEMORY_REPO`, but nothing read it at session start, and a second shared-memory line in `collab-watch.sh` shared the one cursor file and the one lock, so it was refused or skipped. New instance file `.claude/rules/shared-memory-channels.json` (template `templates/rules-instance/shared-memory-channels.json`), parsed in one place, `scripts/shared_channels.py`: a list of `{label, repo, members, interval}`; `members` are audience tokens resolved through that channel's own `parties.json`, so a device that is no member neither reads nor watches it. The default shared memory stays the first channel and is never listed: its cursor, lock and ids keep their names, and no file (or an empty list) prints exactly what it printed before. Readers: `helpers/shared-memory-check.sh` runs once more per channel (cursor `shared-memory-state-<label>.json`, every line `shared-memory [<label>]`); `open-items.py` reads every member channel (ids `<label>:<path>`, `--classify` takes them, a listed channel without a clone or a broken file is NOT checked, never "nothing open"); `collab-watch.sh` arms one watcher per channel (cursor `shared-memory-cursor-<label>.json`, lock dir `shared-memory-<label>/`, finds tagged `[<label>]`), names a channel it does not watch, and a broken channel file stops the channels, not the PR watches; `watch-gate.cjs` case (a) holds for a push into any listed channel; `session-closing.sh` names unpushed work in every channel. Fixture `scripts/test-shared-memory-channels.sh` (59 checks, sandbox repos): no file and an empty list unchanged, two channels read and labelled with their own cursors, a non-member channel silent, missing clone and broken file loud, collab-watch with both channels armed at once; 22 of the 59 fail against the code it replaces.
